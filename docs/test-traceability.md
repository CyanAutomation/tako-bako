## Soyuz workflow contracts

Both scheduled workflows run only on the `main` branch in the `soyuz` GitHub environment. They validate `SOYUZ_BASE_URL` against the approved Soyuz origin, use Node 26, request only `contents: read`, and disable persisted checkout credentials. Separate repository-scoped concurrency groups prevent overlapping submissions of the same sweep without cancelling an in-progress submission. Each job has a 15-minute limit and posts a patch-mode pull request task to `/v1/runs` with an idempotency key, a maximum diff of 102,400 bytes, and an execution limit of 10,800 seconds. Only HTTP 200 and 202 responses count as accepted; returned UUIDv7 run IDs, display IDs, and statuses are validated before being written to workflow outputs. Workflow summaries report admission and the status at submission time, not remote completion. The documentation sweep is restricted to `README.md` and Markdown under `docs/`; the DRY sweep is restricted to application, API, server, and test code and makes at most one focused refactor. The separate network-dependent external-link check also runs only on `main`.
